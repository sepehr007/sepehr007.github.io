# کشف اتاق‌ها و جست‌وجوی یکپارچه — بخش ۲۲

این بخش کشف عمومی اتاق‌ها و جست‌وجوی یکپارچه (اتاق/کاربر/دوست/پیام) را کامل می‌کند.
فقط داده‌ای نمایش داده می‌شود که خود کاربر اجازهٔ دیدنش را دارد؛ هیچ اتاق خصوصی یا پیام خصوصی
در هیچ خروجی عمومی (فهرست، جست‌وجو، پیشنهاد، پیشنهاد خودکار) ظاهر نمی‌شود.

## سمت سرور

- `server/stores/discover.js` (جدید)
  - قانون پایه: `visibility = 'public' AND is_active = 1 AND deleted_at IS NULL`
  - `discoverRooms(viewerId, { q, sort, page, limit, filter })`
    - مرتب‌سازی: `activity` (پیش‌فرض)، `members`، `newest`، `name`
    - فیلترها: `open` (جا دارد)، `nopass` (بدون رمز)، `active` (فعال در ۲۴ ساعت)
    - خروجی: `{ rooms, total, page, limit, hasMore, sort, filters }`
  - `suggestRooms(viewerId, q, limit)` — پیشنهاد سریع نام اتاق (حداقل ۲ کاراکتر)
  - `recommendRooms(viewerId, limit)` — فقط با سه دلیل قابل اثبات:
    - `friend` — اتاقِ یک دوست (با نام دوست)
    - `live` — اتاقی با عضو فعال در ۶۰ دقیقهٔ اخیر
    - `fresh` — اتاقی که کمتر از ۲۴ ساعت از ساختش گذشته
    - اتاق‌های خود کاربر و اتاق‌هایی که قبلاً عضو شده حذف می‌شوند.
- `server/routes/rooms.js` — `GET /discover`، `GET /suggest`، `GET /recommend` (پشت `features.publicDiscovery`، قبل از مسیر `/:code` تعریف شده‌اند)
- `server/stores/social.js` — `sqlSearch` بازنویسی شد:
  - دامنه‌ها: همه / کاربران / دوستان / اتاق‌ها / پیام‌ها
  - مرتب‌سازی: `relevance` (پیش‌فرض)، `recent`، `name`، `members`
  - فیلتر اتاق‌ها: `open`، `nopass`، `active`
  - امتیازدهی تطبیق در JS (نام ۱۰۰، کد اتاق ۹۰، توضیح ۴۵، نام مدیر ۴۰…)
  - پیام‌ها فقط از اتاق‌های عمومی؛ خروجی شامل `total`، `counts`، `hasMore`
- `server/routes/social.js` — `/search` پارامترهای `sort` و `filter` را رد می‌کند.

## سمت مرورگر

- `rooms.html` / `rooms.js` / `rooms.css`
  - جست‌وجو با debounce و `datalist` (تاریخچهٔ محلی + پیشنهاد سرور)
  - چیپ‌های فیلتر، انتخاب مرتب‌سازی، تعداد نتایج، اسکلتون لودینگ، «اتاق‌های بیشتر»
  - تاریخچهٔ جست‌وجو در `localStorage` با کلید `wt.searchHist.v1:<userId>` (حداکثر ۸ مورد)
  - بخش «پیشنهاد برای تو» با برچسب دلیل (دوست/زنده/تازه)
  - حالت خالی جدا برای «هیچ اتاقی نیست» و «فیلتر/جست‌وجو نتیجه نداد»
- `social.html` / `social.js`
  - نوار جست‌وجوی یکپارچه با `datalist`، مرتب‌سازی، شمارش، «نتایج بیشتر»
  - نتیجهٔ اتاق شامل توضیح کوتاه و ذخیرهٔ عبارت در تاریخچه

## تست

- `sec22-smoke.mjs` — ۲۵ بررسی API: فیلترها، مرتب‌سازی، صفحه‌بندی، حریم خصوصی
  (اتاق خصوصی/لینکی هرگز در فهرست، جست‌وجو، پیشنهاد و پیشنهادها نیست)، دلیل پیشنهاد دوست،
  پیام‌ها فقط از اتاق عمومی، رد کوئری کوتاه‌تر از ۲ کاراکتر.
- `sec22-ui.mjs` — ۳۰ بررسی UI با Chrome headless و سرور تازه:
  رندر فهرست، عدد کل، پیشنهادها، پیشنهاد تایپ، جست‌وجو روی توضیح، حالت خالی، تاریخچه،
  فیلتر رمزدار، مرتب‌سازی، «بیشتر»، جست‌وجوی یکپارچهٔ شبکه، صفر خطای کنسول.
- هر دو ۱۰۰٪ قبول.

## محدودیت‌های صادقانه

- جست‌وجو با `LIKE` روی SQLite است؛ ایندکس FTS ندارد. برای تعداد اتاق/پیام کم تا متوسط سریع است،
  برای دادهٔ خیلی زیاد کند می‌شود (سقف داخلی ۲۰۰ ردیف اتاق پیش از امتیازدهی).
- پیشنهادها قانون‌محور است، نه یادگیری ماشین؛ فقط سه دلیل بالا.
- تاریخچهٔ جست‌وجو فقط روی همان مرورگر ذخیره می‌شود و به سرور نمی‌رود.
- پیشنهاد خودکار به «اکنون» وابسته است؛ در بازه‌های ۶۰ دقیقه/۲۴ ساعت دوباره ارزیابی می‌شود و
  ممکن است بین دو بازدید تغییر کند.
